## Architecture Overview

### Stack Decisions

- **State Management:** TanStack Query (React Query v5) for server state, built-in `useState` for UI
- **Real-Time Layer:** Node.js `ws` WebSocket server + EventEmitter pub/sub
- **Backend:** Hono (via React Router v7) on Node.js runtime
- **Database:** Neon Postgres (serverless) — unchanged
- **AI Integration:** Google Gemini 2.5 Flash (via Create platform proxy)
- **Styling:** Tailwind CSS 3 + CSS-in-JS (`styled-jsx` for global styles)

### Data Flow

```
Visitor → ChatWidget → /api/chat → Gemini AI
                              ↓
                    LEAD_DATA extracted → INSERT into DB
                              ↓
                    Event emitted via pubsub → broadcast via WebSocket
                              ↓
                    Dashboard clients receive → React Query cache patched → UI updates instantly
```

## Lead Scoring Algorithm

**Dual-layer scoring:**

1. **AI Score** — generated by Gemini based on conversation context (`High`, `Medium`, `Low`)
2. **Keyword Score** — computed server-side fallback (`src/utils/leadScoring.ts`)

**Keyword buckets:**
- High: "bulk", "wholesale", "urgent", "asap", "purchase order", "MOQ", "container", etc.
- Medium: "quote", "pricing", "catalog", "samples", "negotiate", "lead time", etc.
- Low: "just browsing", "maybe", "research", "comparing", "future", etc.

**Bonus modifiers:**
- Quantity mentions >= 1000 units → +2 High
- Quantity >= 100 units → +1 Medium
- Urgency words ("today", "this week") → +1 High

## Setup Instructions

### 1. Database Migration

Run the SQL migration on your Neon Postgres database:

```bash
# From sokogate-ai/apps/web
psql $DATABASE_URL -f src/db/migrations/001_add_lead_fields.sql
```

Or connect via Neon dashboard and execute the SQL manually.

**SQL:**
```sql
ALTER TABLE leads
  ADD COLUMN IF NOT EXISTS category VARCHAR(100),
  ADD COLUMN IF NOT EXISTS payment_status VARCHAR(20) DEFAULT 'pending',
  ADD COLUMN IF NOT EXISTS shipping_status VARCHAR(20) DEFAULT 'pending',
  ADD COLUMN IF NOT EXISTS shipping_tracking_number VARCHAR(100),
  ADD COLUMN IF NOT EXISTS keyword_score VARCHAR(10),
  ADD COLUMN IF NOT EXISTS source VARCHAR(20) DEFAULT 'chat';

CREATE INDEX IF NOT EXISTS idx_leads_category ON leads(category);
CREATE INDEX IF NOT EXISTS idx_leads_payment_status ON leads(payment_status);
CREATE INDEX IF NOT EXISTS idx_leads_shipping_status ON leads(shipping_status);
```

### 2. Install Dependencies

WebSocket library (`ws`) is already in `package.json`. Ensure it's installed:

```bash
cd apps/web && npm install
```

### 3. Environment Variables

No new env vars required. Ensure `DATABASE_URL` is set.

### 4. Start Dev Server

```bash
cd apps/web
npm run dev
```

The server starts on `http://localhost:4000` (configured in `vite.config.ts`).

WebSocket will automatically attach to the same port at `/api/ws`.

## Performance Notes

- **React Query** cache updates avoid network round-trips for real-time events
- **WebSocket** uses binary framing by default (text frames for JSON); negligible overhead
- **Database** queries are indexed on new columns
- **Lead Scoring** runs in O(n) time where n = number of keywords (~40 total); negligible for chat-length strings
- **Category Detection** uses first-match logic across 8 categories with ~10 keywords each — O(1) for practical purposes

## Known Limitations & Future Work

| Limitation | Recommendation |
|------------|----------------|
| WebSocket doesn't auto-reconnect on client disconnect | Add reconnection logic with backoff in `useRealtimeLeads` |
| No authentication on `/api/ws` endpoint | Add session/Cookie check before allowing WS upgrade |
| Analytics not broadcast on lead changes | Add `serverEvents.emitAnalytics()` in leads API after mutations |
| Category detection is keyword only | Could use AI-provided category exclusively (already in prompt) |
| Payment/shipping updates require separate PATCH per field | Could batch in future |
| No lead deletion endpoint | Add DELETE /api/leads/:id if needed |
